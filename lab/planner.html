How it works

Every 50 ms the planner builds a set of torque sequences: last step's best plan, shifted by one step, plus random variations of it. It runs each one through a small learned model of the pendulum, adds up a cost for how far each predicted path is from upright, and applies the first torque of the cheapest plan. This page runs a JS port of the integer math in int8-rollout-engine, which matches the Python model exactly.

The pendulum's state is stored as two 8-bit integers. The angle uses steps of π/128, so 0 is upright and it wraps around at ±128. The angular speed uses steps of 8/127 rad/s and stops at ±127. Each motor torque in a plan is also an 8-bit integer.

The learned model takes angle, speed and torque, passes them through 16 hidden units, and outputs the change in angle and speed for one 50 ms step (a 3 → 16 → 2 network, all integer multiply-adds and shifts). Each plan is stepped through it 15 times (or 5, with fewer steps ahead), and every step adds a cost of θ² + 21ω²/32 + u²/2048, in the same integer units. The plan with the lowest total wins. Its remaining torques, shifted by one step, become the starting guess for the next step, and the other plans are random variations around it.

In hardware, the plans are split across parallel lanes. One decision takes (32 / lanes) · (83 · H + 2) + 34 clock cycles, which is 1,281 for the current settings. The 8-lane build runs on a Tang Nano 20K FPGA and takes 186 µs per decision.
